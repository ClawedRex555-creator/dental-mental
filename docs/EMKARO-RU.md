# Подключение домена emkaro.ru

Пошаговая инструкция после покупки домена.

---

## Как это будет работать

| Адрес | Назначение |
|-------|------------|
| **https://emkaro.ru** | Главная: список клиник |
| **https://demo.emkaro.ru/login** | Вход в клинику «demo» (пример) |
| **https://ulybka.emkaro.ru/login** | Другая клиника (когда создадите) |

---

## Шаг 1. DNS у регистратора (где купили emkaro.ru)

Нужен **IP вашего VPS** (из панели Timeweb / Reg.ru / Selectel).

В разделе **DNS / Управление зоной** добавьте записи:

| Тип | Имя (хост) | Значение |
|-----|------------|----------|
| **A** | `@` | `123.45.67.89` ← ваш IP |
| **A** | `*` | `123.45.67.89` ← тот же IP |
| **A** | `www` | `123.45.67.89` ← тот же IP (по желанию) |

- `@` — это сам **emkaro.ru**
- `*` — любой поддомен: **demo.emkaro.ru**, **ulybka.emkaro.ru**
- Обновление DNS: от **15 минут до 24 часов**

Проверка (с компьютера):

```bash
nslookup emkaro.ru
nslookup demo.emkaro.ru
```

Оба должны показать ваш IP.

### Reg.ru (частый случай)

1. Домены → **emkaro.ru** → **DNS-серверы и управление зоной**
2. Если зона пустая — «Добавить запись» → тип **A**
3. Поддомен оставить пустым или `@` для корня
4. Для `*` — в поле «Поддомен» иногда пишут `*` или `*.emkaro.ru` (смотрите подсказку Reg.ru)

## Шаг 2. Сервер (VPS)

Минимум: **Ubuntu 22.04**, **2 GB RAM**, порты **80** и **443** открыты в firewall.

```bash
# Порты для HTTPS (обязательно для emkaro.ru)
# 80  — проверка Let's Encrypt
# 443 — сайт
```

Порт **3000** для быстрого теста по IP больше не нужен, если идёте через домен.

---

## Шаг 3. Установка Emkaro на сервер

```bash
cd /opt
# загрузите проект (git clone или zip)
cd emkaro   # или dentalcloud-mis — как назвали папку

cp .env.example .env
nano .env
```

Заполните **`.env`**:

```env
NODE_ENV=production
AUTH_SECRET=вставьте-длинную-случайную-строку
APP_ROOT_DOMAIN=emkaro.ru
ACME_EMAIL=ваш@email.ru
POSTGRES_PASSWORD=сильный-пароль-базы
ENABLE_DEMO_ACCOUNTS=false
```

Сгенерировать секрет (на сервере):

```bash
openssl rand -base64 48
```

Запуск **с HTTPS и поддоменами**:

```bash
docker compose up -d --build
```

Подождите 2–5 минут. Caddy сам получит SSL-сертификат для `emkaro.ru` и `*.emkaro.ru`.

Логи:

```bash
docker compose logs -f caddy
docker compose logs -f app
```

## Если раньше тестировали по IP (:3000)

Остановите быстрый вариант и перейдите на домен:

```bash
docker compose -f docker-compose.quick.yml down
docker compose up -d --build
```

В `.env` должно быть `APP_ROOT_DOMAIN=emkaro.ru`, без `DEFAULT_CLINIC_SLUG` (или закомментируйте — он только для IP).

## Частые проблемы

| Проблема | Решение |
|----------|---------|
| «Сайт не открывается» | DNS ещё не обновился; проверьте A-записи и IP |
| «Клиника не найдена» | Создайте клинику через `create-clinic` с тем же **slug**, что в поддомене |
| Нет HTTPS / ошибка сертификата | Порты 80 и 443 открыты? DNS уже указывает на сервер? |
| `www.emkaro.ru` не работает | Добавьте A-запись для `www` |
| Вход только на emkaro.ru без поддомена | Нужен **demo.emkaro.ru**, не корень |

## Почта на домене (Яндекс 360 / Яндекс.Почта для домена)

Сейчас у **emkaro.ru** DNS на **Timeweb** (`ns1.timeweb.ru` …), MX-записи по умолчанию:

| Приоритет | Значение |
|-----------|----------|
| 10 | `mx1.timeweb.ru` |
| 20 | `mx2.timeweb.ru` |

Чтобы письма на `@emkaro.ru` шли в **Яндекс**, замените MX по инструкции Яндекса.

### Шаг 1. Панель Timeweb

1. [timeweb.cloud](https://timeweb.cloud) → **Домены** → **emkaro.ru**
2. Раздел **DNS / Управление зоной** (или **Редактор DNS**)

### Шаг 2. Удалить старые MX

Удалите **все** существующие MX-записи:

- `mx1.timeweb.ru`
- `mx2.timeweb.ru`
- любые другие MX, если есть

### Шаг 3. Добавить MX Яндекса

Одна новая запись:

| Поле | Значение |
|------|----------|
| **Тип** | MX |
| **Хост / поддомен** | `@` (или **пусто** — корень домена) |
| **Приоритет** | `10` |
| **Значение / сервер** | `mx.yandex.net.` (точка в конце — нормально) |
| **TTL** | `21600` (если поле есть; иначе по умолчанию) |

В Timeweb иногда поле «Значение» без точки в конце — обычно работают оба варианта: `mx.yandex.net` или `mx.yandex.net.`

### Шаг 4. Проверка

Подождите **15 минут – 72 часа**, затем:

```bash
dig @8.8.8.8 MX emkaro.ru +short
```

Ожидается:

```text
10 mx.yandex.net.
```

В кабинете Яндекса (Подключение домена → **Проверить**) нажмите **Проверить**, когда dig показывает новую запись.

### DKIM (обязательно для исходящей почты)

Яндекс ищет запись именно на **`mail._domainkey.emkaro.ru`**, не на корне домена.

**Ошибка, если уже добавляли:** TXT с `v=DKIM1;…` повесили на хост `@` / `emkaro.ru` — Яндекс такую запись **не видит**.

#### В Timeweb → Домены → emkaro.ru → DNS → TXT

1. Если есть TXT на хосте **`emkaro.ru` / `@`** со значением начинающимся на `v=DKIM1` — **удалите** её (SPF `v=spf1 …` на корне оставьте).
2. **Добавить запись**:

| Поле | Значение |
|------|----------|
| **Тип** | TXT |
| **Хост / поддомен** | `mail._domainkey` |
| **Значение** | скопируйте **целиком** из кабинета Яндекса (кнопка копирования рядом со значением) |
| **TTL** | `600` или по умолчанию |

Пример формата (ваш ключ может отличаться — берите только из Яндекса):

```text
Хост: mail._domainkey
Значение: v=DKIM1; k=rsa; t=s; p=MIGfMA0GCSq...
```

3. Через 5–30 минут проверка:

```bash
dig @8.8.8.8 TXT mail._domainkey.emkaro.ru +short
```

Должна появиться строка с `v=DKIM1`. Затем в Яндексе — **«Проверить снова»**.

### SPF (рекомендуется после MX Яндекса)

Сейчас на корне часто стоит почта Timeweb:

```text
v=spf1 include:_spf.timeweb.ru ~all
```

Для Яндекса замените TXT SPF на корне (`@` / `emkaro.ru`) на значение из мастера Яндекса (обычно `v=spf1 redirect=_spf.yandex.net` или `include:_spf.yandex.net`). Точную строку копируйте из кабинета Яндекса.

### Let's Encrypt в `.env`

`admin@emkaro.ru` в `.env` — адрес для **уведомлений Let's Encrypt** (certbot). Это не обязательно реальный ящик на домене: можно указать любой ваш email (Gmail и т.д.), пока почта на домене не настроена.
